# HTTP再試行のローカル再現

JDK 17が必要です。フレームワークと外部依存はありません。展開したディレクトリで `sh run.sh` を実行します。

- `SampleController.java` は呼び出し側と5ケースの確認です。
- `UserRequestService.java` は要求本文、キー、再試行方針を決めます。
- `AbstractApi.java` はHTTP送受信と応答待ちのタイムアウトを扱います。
- `LocalUserApi.java` はlocalhostだけに一時サーバーを開き、登録した件数をメモリに記録します。最初の応答を返さないケースでも、最初のPOSTは既に保存されています。

| 確認 | 要求 | 保存 |
|---|---:|---:|
| GETの応答待ちで再試行 | 2 | 0 |
| キーなしPOSTの無条件再試行 | 2 | 2 |
| 同じキー・同じ本文のPOSTで再試行 | 2 | 1 |
| 同じキー・異なる本文で2回送信 | 2 | 1、2回目はHTTP 409 |
| キーなしPOSTでタイムアウトしたら停止 | 1 | 1、クライアントは結果を判断できない |

同じキーの判定はこのサーバーが提供する契約です。メモリへの保存は単一プロセス内のデモです。実サービスでは、同じ業務操作を識別するキーのスコープと期限を決め、キーの一意性、処理の保存、再応答する結果を永続化します。
