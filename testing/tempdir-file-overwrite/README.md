# JUnitで既存ファイルが残るか確認する

JDK 17とMaven 3.9系で `mvn test` を実行します。テストはJUnitの `@TempDir` を使うため、普段の作業フォルダにある連携ファイルを変更しません。

- `DirectSnapshotPublisher` は公開ファイルを先に開く故障例です。IOExceptionの後に部分出力が残ることをテストで再現します。
- `SnapshotPublisher` は公開先と同じディレクトリに一時出力し、閉じてから `ATOMIC_MOVE` で切り替えます。書き込み時の失敗で公開ファイルを変更しません。moveが失敗した場合は例外を伝え、非原子的な置換へのフォールバックは行いません。
- 実際のatomic moveの可否はファイルシステムとJavaのファイルシステムプロバイダーに依存します。テストでは `AtomicMoveNotSupportedException` と、既存対象の `FileAlreadyExistsException` を環境依存の未確認として扱います。
- 模擬した非対応はアプリケーションの分岐のテストです。運用環境が非対応かどうかを判定するテストではありません。

対象は単一プロセスでの通常例外とファイル切り替えです。クラッシュ後の永続化、複数プロセスの競合、権限・所有者の引継ぎは対象外です。
